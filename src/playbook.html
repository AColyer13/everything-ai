Project Playbook

A practical, end-to-end checklist for taking a dataset to a model you can trust. It pulls the usual good habits into one workflow.

1. Frame the problem

  • Write the question in one sentence and say what decision it supports.
  • Classify it: regression, classification, clustering, recommendation, or generation.
  • Pick the metric that matches the cost of mistakes (see the metrics table).
  • Decide the baseline to beat: a simple rule, the average, or the current process.

2. Inspect the data

df.shape; df.dtypes; df.head()
df.isna().mean().sort_values(ascending=False).head(10)   # worst missing columns
df.describe(include="all").T
df.duplicated().sum()

Look at the target's distribution first. Check class balance before anything else.

3. Clean and prepare

  1. Remove columns with no information. Zero-variance columns (a single unique value) cannot help any model.
  2. Classify columns automatically by unique-value count: binary, low-cardinality categorical, high-cardinality, numeric.
  3. Handle missing values deliberately: drop, fill with median or mode, or add an "is missing" flag.
  4. Encode categories (one-hot for few levels, target or ordinal encoding for many).
  5. Split first, then fit transformers on the training set only. Fitting a scaler on all the data leaks information from the test set.
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler
from sklearn.impute import SimpleImputer
from sklearn.ensemble import RandomForestClassifier

pre = ColumnTransformer([
    ("num", Pipeline([("imp", SimpleImputer(strategy="median")), ("sc", StandardScaler())]), num_cols),
    ("cat", Pipeline([("imp", SimpleImputer(strategy="most_frequent")),
                      ("oh", OneHotEncoder(handle_unknown="ignore"))]), cat_cols),
])
pipe = Pipeline([("pre", pre), ("model", RandomForestClassifier(random_state=42))])
Practical tip

Write the preparation as a script that works on any new data, not a one-off notebook edit. If the column rules are computed from the data (unique-value counts, data types), the same code keeps working when next month's file arrives with different columns.

4. Build a baseline, then compare

  • Start with something simple: logistic or linear regression. It is fast and sets the bar.
  • Try a tree-based ensemble (random forest, gradient boosting). They are strong defaults on tabular data.
  • Compare models on the same split or cross-validation folds, using the metric from step 1.
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_validate
models = {"logreg": LogisticRegression(max_iter=1000), "rf": RandomForestClassifier(random_state=42)}
for name, m in models.items():
    r = cross_validate(Pipeline([("pre", pre), ("m", m)]), X_train, y_train, cv=5, scoring=["f1", "roc_auc"])
    print(name, r["test_f1"].mean().round(3), r["test_roc_auc"].mean().round(3))

5. Diagnose

You seeLikely causeTry
Train and validation both poorUnderfittingRicher features, more flexible model
Train great, validation poorOverfittingMore data, regularization, simpler model, early stopping
Great accuracy, bad recall on the rare classImbalanceBetter metric, class weights, SMOTE on train only
Test score far above anything realisticData leakageCheck that no feature reveals the answer or comes from the future
Code error you cannot explainBad assumption about the dataPrint the shapes, dtypes and unique values. Debug the data, then the code

6. Tune and evaluate once

Tune hyperparameters with cross-validation on the training data. Touch the test set once, at the very end, to get an honest final number. Report the metric together with a confusion matrix and a sentence on where the model fails.

7. Explain it

  • Show feature importance or SHAP values.
  • Give one or two concrete example predictions, right and wrong.
  • State the limits: what data it was trained on, and where it should not be trusted.

8. Ship and monitor

  • Save the whole pipeline (joblib.dump(pipe, "model.joblib")), not just the model, so preprocessing travels with it.
  • Log inputs and predictions. Watch for data drift (inputs change) and concept drift (the relationship changes).
  • Set a retraining trigger and keep the previous version for rollback.
