Python projects

Analyzing Customer Orders Using Python

Goal: turn a table of orders into answers: revenue by product, best customers, busy periods.

How AI does it: this one is mostly not machine learning. It is the foundation AI sits on: load the data with pandas, clean it, group and aggregate, then chart it. The "AI" part is optional: a language model can draft the pandas code from a plain-English question, and a simple model can later predict repeat buying from the same cleaned table.

Watch out: duplicate orders, missing prices and mixed date formats quietly corrupt totals. Check df.duplicated().sum() and df.isna().mean() first.

Building a Python Adventure Game with GitHub Copilot

Goal: build a text adventure while using an AI coding assistant.

How AI does it: Copilot is a large language model trained on code (see Generative AI). You describe what you want in a comment or prompt ("a function that moves the player between rooms and updates inventory") and it predicts the next lines. You supply the design: rooms as a dictionary, a game loop, classes for player and items (the Python OOP section). The assistant writes boilerplate; you decide structure and review everything.

Watch out: it produces plausible code, not guaranteed-correct code. Run it, test the edge cases (invalid commands, empty inventory) and read what it wrote.

Data science projects

Retail Analysis with Walmart Data

Goal: understand and predict store sales, and see how holidays, temperature, fuel price, CPI and unemployment affect them. (This matches the well-known Walmart weekly-sales dataset; confirm against your brief.)

How AI does it: frame it as regression on weekly sales. Steps: parse dates and add week, month and holiday features; explore which stores and weeks are strongest; check correlations; fit a linear regression, then a random forest or gradient boosting, and compare RMSE. Because the data is ordered in time, split by date (train on the past, test on the future), not randomly.

Watch out: a random split leaks the future into training. Correlation between, say, fuel price and sales is not proof of cause.

Sales Analysis

Goal: find what drives sales: top products, regions, months, discounts.

How AI does it: exploratory data analysis first (group-bys, pivot tables, plots), then optional modelling: a regression to estimate how discount or season changes revenue, or a tree model whose feature importances rank the drivers. Plots and a clear written conclusion matter as much as the model.

Watch out: outliers (one huge order) can dominate averages; compare medians too.

Marketing Campaigns

Goal: find which customers respond to campaigns and what separates them.

How AI does it: two classic routes. Segmentation: scale the features and use k-means to group customers, then describe each group (age, income, spend). Response prediction: a classifier such as logistic regression or random forest that outputs the chance a customer accepts an offer. Hypothesis tests (t-test, chi-square, from Data Science) check whether a difference between groups is real.

Watch out: response rates are usually low, so accuracy misleads. Use precision, recall and F1 (see Machine Learning).

Machine learning projects

Mercedes-Benz Greener Manufacturing

Goal: predict how long a car takes on the test bench from hundreds of anonymous features, so testing time (and emissions) can be cut. (Based on the public Kaggle competition of the same name.)

How AI does it: a regression problem with many binary columns and few rows. Remove zero-variance columns (no information), check for duplicates, encode the few categorical columns, reduce dimensions with PCA, then fit a regressor, usually gradient boosting such as XGBoost, and measure R² or RMSE. This is exactly the "remove columns with a single unique value" step in the Playbook.

Watch out: with more features than the data supports, models overfit. Cross-validate, and keep the preprocessing inside a pipeline.

Creating Cohorts of Songs

Goal: group songs into cohorts that sound alike, for playlists or recommendations. (Typically built on Spotify-style audio features.)

How AI does it: unsupervised clustering. Pick audio features (danceability, energy, tempo, valence, and so on), standardize them, optionally reduce with PCA, and run k-means. Choose k with the elbow method or silhouette score, then profile each cluster by its average features and give it a name ("calm acoustic", "high-energy dance"). Hierarchical clustering is a good cross-check.

Watch out: unscaled features make tempo (large numbers) swamp everything else. There is no "right answer" label, so judge clusters by whether they make sense.

Employee Turnover Analytics

Goal: predict who is likely to leave and find out why, so HR can act early.

How AI does it: binary classification (left or stayed). Encode department and salary level, check class balance, and handle imbalance with class weights or SMOTE on the training set only. Compare logistic regression, random forest and gradient boosting. Use recall and ROC-AUC, since missing a person who is about to leave is the costly error. Feature importance then turns the model into advice (workload, satisfaction, tenure).

Watch out: a model that is accurate but cannot be explained is hard for HR to use. Report the drivers, not only the score.

Deep learning projects

Lending Club Loan Data Analysis

Goal: predict whether a borrower will repay a loan.

How AI does it: tabular classification with a neural network. Clean and encode the loan features, scale the numeric ones, handle the heavy class imbalance, then train a small feed-forward network (dense layers, ReLU, dropout, sigmoid output) with early stopping, as in the Deep Learning Keras example. Compare it honestly with a random forest: on tabular data, tree models often match or beat neural nets.

Watch out: data leakage. Columns recorded after the loan was issued (such as payment totals) reveal the answer. Also consider fairness: credit models can encode bias.

House Loan Data Analysis

Goal: predict which home-loan applicants will have difficulty repaying. (Likely the Home Credit style dataset; check your brief.)

How AI does it: the same recipe as above on a wider table: many columns, many missing values, a rare "default" class. Impute, encode, scale, split, train a neural network, and judge it with recall, precision and ROC-AUC rather than accuracy. Tune the decision threshold to match the business cost of a missed default versus a rejected good customer.

Watch out: a 92% accurate model that predicts "repays" for everyone is useless. Check the confusion matrix.

Automating Port Operations

Goal: use AI to automate a port task. The exact task depends on the brief; the likely version is recognizing ships, containers or vessels in images.

How AI does it: computer vision. If the job is "what type of vessel is this?", fine-tune a pretrained CNN with transfer learning (freeze early layers, train a new head). If it is "where are the containers or ships?", use object detection such as YOLO to draw boxes. Add augmentation (flips, crops, lighting) because port photos vary a lot, and evaluate on images the model never saw.

Watch out: small image sets overfit quickly. Transfer learning and augmentation are the fix, not a bigger model.

End-to-end projects

Preserving Heritage: Enhancing Tourism with AI

Goal: the title suggests using AI to protect cultural sites and improve the visitor experience. The exact deliverable is not known from the title, so this entry lists the usual building blocks.

How AI could do it:

  • Recognize monuments from photos with a pretrained image model fine-tuned on landmark images.
  • Answer visitor questions with a language model plus RAG, or an LLM Wiki built from the guide book and site history, so answers are grounded in real sources (see Generative AI).
  • Recommend routes and sites with a recommender system from visitor ratings or interests.
  • Monitor condition by flagging cracks or damage in images with anomaly detection or classification.

Watch out: generated descriptions of historical facts can be wrong. Ground them in vetted sources and cite them.

Sales Forecasting

Goal: predict future sales, per product or store, to plan stock and staffing.

How AI does it: time-series forecasting. Start with a naive baseline ("same as last week"), then build features (lags, rolling averages, calendar, holidays, promotions) and fit gradient boosting, or use a dedicated model (ARIMA or Prophet) or an LSTM from the Deep Learning page. Validate with a walk-forward split (train on the past, test on the next period), and report MAE or RMSE against the baseline.

Watch out: random train/test splits leak the future. If a fancy model cannot beat the naive baseline, say so.

Autonomous Driving

Goal: build a perception component of a self-driving system, such as detecting road objects or predicting steering from camera images.

How AI does it: computer vision with deep learning. Object detection (YOLO-style) finds cars, pedestrians and signs; a CNN can classify traffic signs or predict a steering angle directly from the image (end-to-end "behavioural cloning"); segmentation labels each pixel as road, lane or obstacle. Train with heavy augmentation, validate on unseen roads and weather, and measure with precision, recall and mAP for detection.

Watch out: safety. Rare situations (night, fog, unusual objects) are exactly where models fail, so test them explicitly. This is why real systems combine several sensors and human oversight.

The same four habits show up in every project: inspect the data first, split before you transform, pick a metric that matches the cost of mistakes, and compare against a simple baseline.
