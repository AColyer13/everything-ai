Hardware

How fast each kind of AI hardware really is, measured by memory bandwidth, and the best job each one can do: NVIDIA B200, RTX 5080, DGX Station, DGX Spark, Apple M5 Ultra, M5 Max and M6.

Not from the class

This page is a reference added on top of the course content. Specs are a snapshot from November 2026 taken from vendor pages and secondary coverage, and some are rumors (marked below). Speeds shown are theoretical ceilings; real-world results are typically about half. The models these machines run, and the software, are on the Models and Tools pages.

The parts of a computer, and what each does for AI

Four components decide how a machine runs a model. Knowing each one explains the bandwidth numbers further down.

PartWhat it doesRole in AITypical speed
CPU (central processing unit)A few to a few dozen powerful cores that run the operating system, programs and logic one step after another, very flexiblyRuns your code, loads data, schedules the work, tokenizes text. Can run small models on its own, but slowlyDual-channel DDR5 memory feeds it about 60 to 100 GB/s
GPU (graphics processing unit)Thousands of simpler cores that do the same math on huge arrays at onceThe engine of AI. Neural networks are mostly matrix multiplication, which is exactly what GPUs parallelize. Used for both training and running modelsIts own fast memory: about 1 TB/s on a gaming card, about 8 TB/s on a data-center GPU
RAM (system memory)Fast, temporary working storage that loses its contents when the power goes offHolds the model weights and the KV cache while the model runs. A model that does not fit in the GPU's memory spills into RAM, which is slower. On the Mac and DGX Spark, RAM is unified: CPU and GPU share one poolAbout 60 to 100 GB/s for desktop DDR5; 273 GB/s to 1.2 TB/s for unified memory on the machines below
PCIe SSD (NVMe solid-state drive)Permanent storage that survives power-off, connected over the PCIe busStores the model files (a large model is tens to hundreds of GB), checkpoints and datasets. Loading a model reads it from the SSD once. Tools such as Strata can also stream rarely used weights from the SSD as a last resortPCIe 4.0 drives read about 7 GB/s, PCIe 5.0 drives about 12 to 14 GB/s

PCIe: the road between the parts

PCIe is the connection that links the GPU, SSDs and other devices to the CPU. A PCIe 5.0 x16 slot (the usual graphics-card slot) moves about 64 GB/s each way, far less than the GPU's own memory. That is why a model should live entirely in the GPU's memory: every time the GPU has to fetch weights across PCIe from system RAM, speed collapses to PCIe speed, and fetching from the SSD is slower still.

RAM versus VRAM, and why unified memory helps

RAM (system memory)VRAM (video memory)
Lives onThe motherboard, in slots next to the CPUThe graphics card, soldered beside the GPU
Used byThe CPU (and the GPU, slowly, over PCIe)The GPU directly
TypeDDR5GDDR7 on gaming cards, HBM on data-center cards
BandwidthAbout 60 to 100 GB/sAbout 1 TB/s on an RTX 5080, about 8 TB/s on a B200
SizeCheap to expand: 32 to 256 GBExpensive and fixed: 16 GB on a 5080, 32 GB on a 5090, up to about 192 GB on a B200

On a typical x86 PC these are two separate pools. A model that fits in VRAM runs at full GPU speed. A model that does not fit has to spill its extra layers into system RAM, and every token then pays the price of reading those layers from RAM.

How much slower it gets

Example: a 24 GB model on a 16 GB RTX 5080, with 16 GB of it in VRAM (about 960 GB/s) and the remaining 8 GB in DDR5 RAM (about 80 GB/s). Per token the machine reads each part once:

CaseTime per tokenCeiling speed
All 24 GB in VRAM (a card with enough memory)24 ÷ 960 = 0.025 sabout 40 tokens/s
16 GB in VRAM + 8 GB in RAM16 ÷ 960 + 8 ÷ 80 = 0.117 sabout 8.5 tokens/s
Everything in RAM, CPU only24 ÷ 80 = 0.30 sabout 3 tokens/s

So putting just one third of the model in RAM makes generation about 5 times slower, and running entirely from RAM is roughly 10 to 15 times slower than VRAM, because VRAM bandwidth is that much higher. The slow part dominates: the more of the model that spills, the closer you get to RAM speed. Loading from an SSD is slower again (about 12 to 14 GB/s). These are ceilings; real slowdowns are often worse because data also crosses the PCIe link.

Mixture-of-experts models soften the blow, since only a few experts are read per token, so keeping the always-used parts in VRAM and the rarely used experts in RAM costs less. This is the trick behind running a 125B model on a 16 GB card with Strata, and why it is slower than a model that fits.

Unified memory: one pool

Apple's M-series chips and the NVIDIA DGX Spark put the CPU and GPU on the same chip package sharing one pool of memory. There is no VRAM versus RAM split and no PCIe copy: the GPU can use almost all of the memory at full speed. (NVIDIA's Grace-based DGX Station is a related design: the CPU and GPU memory are joined by a fast coherent link rather than shared in one pool.) Not every ARM chip does this, but the ARM machines built for AI mostly do.

x86 PC with a discrete GPUARM with unified memory
Memory poolsTwo: VRAM and RAMOne
Memory the model can use at full speedOnly the VRAM (for example 16 GB)Nearly all of it (for example 128 or 512 GB)
When the model is bigger than the fast memorySpills to RAM; speed falls 5 to 15 timesNot a problem until the single pool is full
BandwidthVery high, but only for the VRAM partModerate to high (273 GB/s to 1.2 TB/s), across the whole pool
Why this gives ARM an advantage for models

A model needs memory more than anything else. Unified memory turns all of a machine's memory into "VRAM", so a 128 GB DGX Spark or Mac can load models that a 16 GB gaming card can only run by spilling to slow RAM. The trade-off is bandwidth: the gaming card is faster on anything that fits in its 16 GB, and the ARM machine wins on anything bigger.

Why bandwidth sets the speed

When an LLM writes text it generates one token at a time, and for every token the chip must read the model's active weights out of memory. So the generation speed is limited mainly by memory bandwidth, not raw compute:

tokens per second  ≈  memory bandwidth (GB/s)  ÷  GB of weights read per token
  • A dense 70B model at 4-bit reads about 40 GB per token. At 273 GB/s that is at most about 7 tokens per second.
  • A mixture-of-experts model with about 6B active parameters reads only about 3.5 GB per token at 4-bit, so the same chip can be many times faster.
  • Capacity decides whether the model fits at all. Compute decides how fast the machine reads a long prompt (prefill). Bandwidth decides how fast it writes the answer (decode).

What the table teaches

Two things beat raw size: a mixture-of-experts model (reads far fewer weights per token) and more bandwidth. The 16 GB RTX 5080 has more bandwidth than the 128 GB DGX Spark, so it is faster on anything that fits, but the Spark can load models the 5080 cannot.

The best each can do

NVIDIA B200

  • Speed: about 8 TB/s per GPU, the fastest here by a wide margin, and eight of them in a server are linked by NVLink.
  • Best at: training large models, and serving the biggest models to thousands of users at once with high throughput. It is also the best single chip for prompt processing.
  • Limits: not a desktop product, very expensive, usually rented by the hour from a cloud. See the enterprise table on the Models page.

NVIDIA DGX Station

  • Speed: data-center class bandwidth (HBM around 7 to 8 TB/s) in a desk-side machine, with a big pool of slower CPU memory behind it.
  • Best at: running or fine-tuning very large models (hundreds of billions of parameters) at full speed, and serving a whole team from one box with the full CUDA stack.
  • Limits: priced like a server, far above the others. Models that spill from HBM into the CPU memory slow down to about 400 GB/s.

Apple M5 Ultra (Mac Studio)

  • Speed: about 1.2 TB/s, roughly 50% above the M3 Ultra it replaces. Apple announced it in August 2026 with the 512 GB configuration said to arrive in late October; I did not confirm that it has shipped.
  • Best at: the most memory per dollar. It loads huge models (hundreds of billions of parameters at 4-bit) in one quiet machine and runs mixture-of-experts models at comfortable speeds.
  • Limits: slower than NVIDIA at prompt processing and training, and software built only for CUDA will not run.

Apple M5 Max

  • Speed: about 614 GB/s, the 128 GB configuration (the 32-core GPU version has less memory and bandwidth).
  • Best at: a portable machine that runs models in the 30B to 120B range at 4-bit. Mixture-of-experts models in the 100B class run well; dense 70B is usable but slow.
  • Limits: half the bandwidth and a quarter of the memory of the M5 Ultra.

NVIDIA RTX 5080 (16 GB)

  • Speed: about 960 GB/s (256-bit GDDR7; this figure is from the card's specification rather than the sources I searched), faster than the DGX Spark and the M5 Max.
  • Best at: models that fit in 16 GB: Gemma 4 12B QAT, gpt-oss-20b, and 7B to 14B models, all fast. Strong at image generation, and at prompt processing for its price.
  • Limits: only 16 GB. Anything larger spills into slower system RAM, as with Qwen3.8-Flash-Next through Strata.

NVIDIA DGX Spark

  • Speed: about 273 GB/s, the slowest generation here after the base M6.
  • Best at: fitting a 100B-class model in 128 GB with the full CUDA stack, and fine-tuning and development work where the model matters more than tokens per second. Two units can be linked for 256 GB.
  • Limits: dense large models generate slowly because of the bandwidth. Mixture-of-experts models are the good fit.

Apple M6 (base chip)

  • Status: reported by Bloomberg's Mark Gurman and other outlets for late 2026 in a MacBook Pro, built on a 2 nm process. Reports of its bandwidth disagree: about 200 GB/s in most, 170 GB/s in two. Treat everything here as unconfirmed.
  • Memory: configurations vary; this page uses up to 64 GB as the working assumption.
  • Entry-level chip: reports say Apple does not plan M6 Pro, Max or Ultra variants and expects bigger chips to follow with the M7 family.
  • Best at (if it matches reports): models up to about the 30B class at 4-bit, and small to mid-size models (1B to 14B) comfortably. At about 200 GB/s it is slow on dense models of that size, so prefer mixture-of-experts models that fit in 64 GB. It cannot hold the 100B-class models.

Linux x86 versus ARM

The machines above use two different CPU families. x86 (Intel and AMD) is the long-standing standard for PCs and servers. ARM is a more power-efficient design used in phones, Apple's M-series chips, the NVIDIA Grace CPU in the DGX Station and the GB10 chip in the DGX Spark. Linux runs on both.

x86 (Intel, AMD)ARM (Apple M-series, NVIDIA Grace, Graviton)
Typical AI machinesGaming PCs and workstations with RTX cards, most GPU servers (HGX/DGX with B200, H100)Mac Studio, MacBook Pro, DGX Spark, DGX Station, AWS Graviton
Memory designSeparate: CPU uses system RAM, GPU has its own VRAM, joined by PCIeOften unified or tightly coupled: CPU and GPU share one fast pool (Apple, Spark) or a coherent link (Grace)
Power and heatHigher; desktops and servers draw hundreds of wattsLower for the same work, quieter, better on battery
Software compatibilityWidest. Nearly all Linux software, drivers and containers ship x86 builds firstGood and improving, but some packages, prebuilt wheels or Docker images lack an ARM build and need recompiling
UpgradeabilitySwap the GPU, add RAM and SSDsUsually fixed at purchase, especially on Apple where memory is soldered to the chip
Max memory for modelsGPU VRAM is the limit (16 to 192 GB per GPU) unless you add multiple GPUsLarge single pools (128 to 512 GB) at modest cost
Raw GPU speedHighest with discrete NVIDIA cards, which have the best bandwidth and computeApple: good bandwidth, less compute. NVIDIA ARM systems: full CUDA with strong coherence
Cost for large modelsLarge VRAM means expensive data-center GPUsCheaper per GB of model memory

Advantages in plain terms

  • x86 wins on: compatibility (everything just installs), raw GPU speed with a discrete NVIDIA card, flexibility (upgrade and mix parts), and the largest ecosystem for training and servers.
  • ARM wins on: efficiency (performance per watt), quiet and portable machines, and unified memory that lets a small box hold a very large model without a giant GPU.
  • Linux on both: x86 Linux is the default for AI servers. Linux on ARM is increasingly common (DGX Spark runs an NVIDIA Linux build, and cloud ARM instances are cheaper), but check that your Python packages and containers have ARM builds before you commit. On a Mac, macOS plus tools like MLX, Ollama and LM Studio replace the Linux stack.
Rule of thumb

Choose x86 + NVIDIA GPU when you want maximum speed on models that fit in VRAM, or you need to follow tutorials and tools that assume CUDA. Choose ARM with unified memory (Apple or DGX Spark) when you want to run models too big for any single gaming GPU at a reasonable price and power draw.

Buy for the model you want to run

Start from the model: its size at 4-bit decides the memory you need, whether it is dense or mixture-of-experts decides the bandwidth you need, and your tolerance for slow prompt processing decides Apple versus NVIDIA.
