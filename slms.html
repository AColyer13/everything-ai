SLMs

A small language model (SLM) is a language model small enough to run on a laptop, a single GPU or even a phone, instead of a data-centre cluster. This page explains what counts as small, why SLMs matter, what they are good and bad at, and where the technology is heading, including chips that have a model built directly into the silicon.

About this page

"Small" is a moving target and the field changes monthly, so treat model names and numbers as a snapshot from November 2026. Where a number comes from a vendor's own testing, the page says so.

Talk to a model on a hardwired chip

Try ChatJimmy (chatjimmy.ai), a public chat demo from the chip company Taalas. It is a small model (Llama 3.1 8B) running on a chip built for that one model, and you can see how fast replies appear. The demo is covered in "The future: a model etched into a chip" below. (The address people often type, jimmychat.ai, does not exist; the working one is chatjimmy.ai.)

What counts as small?

There is no official cut-off. In practice the term covers models from a few hundred million up to roughly 10 to 15 billion parameters, small enough to fit in the memory of ordinary hardware. A frontier model is the opposite: hundreds of billions of parameters or more, run only in a data centre.

Total versus active parameters

Mixture-of-experts models blur the line. gpt-oss-20b has about 21B parameters in total but only about 3.6B active for each token, so it runs like a small model on a 16 GB card even though the file is bigger. Qwen3.8-Flash-Next has 6B active but 125B in total, so you still need room to store all of it. See the Models page.

Why SLMs matter

BenefitWhat it means
PrivacyThe model and your data stay on your own machine, so nothing is sent to a provider.
CostNo per-token bill. After you own the hardware, running the model costs only electricity.
Speed and latencyNo network round trip, and a small model produces tokens quickly on modest hardware.
Offline useWorks on a plane, in a factory or anywhere without a connection.
ControlYou choose the version, set the sampling settings and can fine-tune it on your own data.

How small models got good

  • Better training data. Careful data selection and synthetic data let a small model learn more per token than older, larger ones.
  • Distillation. A big "teacher" model's answers are used to train a small "student", which copies much of its behaviour. See Finetuning an LLM.
  • More training per parameter. The Chinchilla result showed models should see far more tokens for their size, so small models are now trained on much more text than their size once suggested. See Creating an LLM.
  • Quantization. Storing weights in 8 or 4 bits instead of 16 cuts memory by half or three quarters with modest quality loss. Google also ships official quantization-aware-trained Gemma 4 checkpoints.
  • Reasoning modes. Many small models can "think" before answering, trading time for accuracy.

Will it fit? The memory rule of thumb

Memory for the weights is roughly parameters × bytes per weight, plus extra for the context and software. Google's own table for Gemma 4 12B shows the pattern, and it includes about 20% overhead:

PrecisionBytes per weightGemma 4 12B memory (Google)
BF16 (16-bit)226.7 GB
8-bit113.4 GB
4-bit0.56.7 GB

Google notes these figures cover the weights only, not the context window or supporting software. That is why a 4-bit 12B model fits comfortably on a 16 GB GPU while the 16-bit version does not.

What SLMs are good at, and where they fall short

Good fitPoor fit
Summarizing, rewriting, classifying and extracting from textOpen-ended expert reasoning across many fields
Private assistants over your own notes and documentsLong, multi-step coding or research jobs without help
Autocomplete, smart replies, on-device featuresObscure facts, which a small model is more likely to get wrong or invent
One narrow task, especially after fine-tuningAnything where a frontier model's extra judgment is worth paying for
Fast, cheap, high-volume jobsVery long documents unless the model has a large context window and enough memory for it
Check vendor benchmarks

When Alibaba launched its Qwen3.5 small series (0.8B, 2B, 4B and 9B, with a 262K-token context and an Apache 2.0 licence), its own results said the 9B matched or beat much larger models on several tests. Independent scorers such as Artificial Analysis rated it well for its size, but also placed it below frontier models. Vendor claims are a starting point; test on your own task.

The future: where SLMs are heading

Several trends point the same direction. These are our reading of the coverage, not guarantees.

  • Many small models instead of one giant one. Analysts expect systems built from several small models, each doing one job well, with a larger model called in only for hard questions.
  • AI built into devices. Phones and laptops increasingly ship with a small model on board, so features work privately and offline.
  • Agents that run locally. Coding and assistant tools can already use a local model through Ollama and similar tools. As small models improve at calling tools, more agent work moves onto your own machine. See Tools and MCP.
  • Specialized hardware. Instead of general GPUs, some companies are designing chips around a single model, which is the next section.

The future: a model etched into a chip

A normal chip loads a model's weights from memory every time it generates a token, and moving that data is the main bottleneck. Taalas, a chip company, takes a different approach: it turns a specific model into custom silicon, so the weights live in the hardware itself.

ItemWhat Taalas says or coverage reports
ChipHC1, a "technology demonstrator" on TSMC 6nm with 53 billion transistors, sold as part of a 2.5 kW server
ModelMeta's Llama 3.1 8B, built into the chip
Speed claimAbout 17,000 tokens per second per user (Taalas's own test). One analyst reportedly measured about 14,357 tokens per second.
ComparisonThe same model on an NVIDIA H200 is reported at roughly 230 tokens per second in one source
Trade-offsThe chip runs one model only. It uses aggressive low-bit quantization (about 3 to 6 bits), which one reviewer says clearly hurts quality in this first version. It does support LoRA fine-tuning and a configurable context window.

The company's pitch is that a "hardcore model" can be far cheaper and more efficient than the same model in software. That is a vendor claim and the technology is early. Two cautions: this is a data-centre server reached over the internet, not something in your pocket, and a chip locked to one model is out of date when a better model arrives. But if the approach scales, near-instant local-quality AI could become cheap enough to put almost anywhere.

Try it: open chatjimmy.ai and ask for a long answer. Replies appear almost all at once, far faster than a typical chatbot. Because it is only an 8B model, expect shallower answers than a frontier model gives.
