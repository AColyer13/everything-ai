LLM

Building a language model from scratch: what fits on one RTX 5070 Ti, the seven stages, a starter configuration, and when to rent GPUs. Written Nov 4, 2026 by Adam.

Not from the class

This page is a practical guide added on top of the course content. It puts the ideas from Deep Learning (transformers, optimizers) and Generative AI (tokens, pretraining) into a hands-on project. Times, memory and costs are estimates, good to within a factor of about 2. The companion page is Fine-Tuning.

Summary

On one RTX 5070 Ti you can train a GPT-2-class model (about 125M parameters) from random weights in roughly a day, and it will write fluent but shallow English. That is the right first project: you learn every stage, and the same code scales to larger models on rented GPUs.

"From scratch" here means you build the tokenizer, collect the training text, define the transformer, and pretrain it starting from random weights, then teach it to chat. It does not mean matching Qwen or Gemma. Those took trillions of tokens and thousands of GPUs. For a useful domain model, fine-tuning an existing model will beat a home-built one by a wide margin.

Recommended path

Train a tiny model first to check the code works, then a 125M model locally, then, if you want a model that can actually chat, run the same code on rented GPUs for a few hundred dollars.

What fits on your hardware

A 125M model is the sweet spot for an RTX 5070 Ti: about 15 hours of training for a compute-optimal run. Beyond about 350M parameters, training runs take weeks locally and memory gets tight.

How the estimates were made

  • Compute: training compute is about 6 × parameters × tokens. The card peaks at about 88 TFLOPS BF16 dense. Real training reaches roughly 40% of peak, so about 35 TFLOPS.
  • Compute-optimal: uses the Chinchilla rule of about 20 tokens per parameter.
  • Memory rule of thumb: full training with AdamW in mixed precision needs about 16 bytes per parameter (weights, gradients, optimizer state), plus activations. That is why 1B parameters (~16 GB before activations) doesn't fit on 16 GB.

The build at a glance

Pretraining (step 4) uses almost all of the compute; every other stage takes minutes to an hour. If evaluation disappoints, the fix is usually more tokens or a bigger model, so you go back to pretraining.

tokenizer -> data shards -> model -> PRETRAIN (hours to days) -> chat SFT -> evaluate -> export to GGUF
                                         ^                                      |
                                         +--- more tokens or a bigger model ----+

Step-by-step

Seven stages. Get each one working on a tiny model before scaling up.

  1. Tokenizer. Train a byte-level BPE tokenizer (32k–50k vocabulary) on a sample of your training text with Hugging Face tokenizers, or start by reusing the GPT-2 tokenizer through tiktoken. Reserve special tokens now for chat later (<|user|>, <|assistant|>, <|end|>). See minbpe on the AI Pioneers page.
  2. Training data. For a first run, use TinyStories. For the 125M run, use FineWeb-Edu, web text filtered for educational quality. Tokenize everything once into flat binary shards of token IDs (uint16) so training reads them straight from disk. Hold out about 0.5% as validation.
  3. Model architecture. A decoder-only transformer: token embeddings, N blocks of (RMSNorm → causal self-attention with RoPE → RMSNorm → SwiGLU MLP), a final norm, and an output layer tied to the embeddings. Use PyTorch's scaled_dot_product_attention (FlashAttention under the hood). Matching the Llama layout makes the export step much easier.
  4. Pretraining loop. Next-token prediction with cross-entropy loss. BF16 autocast, torch.compile, AdamW (lr ~6e-4, betas 0.9/0.95, weight decay 0.1), warmup then cosine decay, gradient clipping at 1.0. Use gradient accumulation to reach about 0.5M tokens per step. Log training and validation loss, save a checkpoint every hour, and print a text sample every few thousand steps.
  5. Chat fine-tuning (SFT). The pretrained model only continues text. To make it answer questions, fine-tune on conversations formatted with your special tokens, for example SmolTalk, and compute the loss only on assistant turns. This takes minutes to an hour.
  6. Evaluation. Track validation loss, plus a standard benchmark such as HellaSwag. Read the samples yourself: loss going down doesn't guarantee the text is getting better.
  7. Export and run. Save in Hugging Face format with a LlamaForCausalLM config, convert with llama.cpp's convert_hf_to_gguf.py, and load it with ollama create. At 125M parameters it runs instantly on CPU.

Starter configuration (~125M parameters)

This is GPT-2 small's shape with modern components, sized for one 16 GB card. For the 10M test run, use 6 layers, 6 heads, width 384 and context 256 on TinyStories.

CheckpointsEvery ~1 hour (enables resuming after a crash)
Out of memory?

Halve the micro-batch and double the accumulation. The effective batch stays the same.

Scaling up: when to rent GPUs

Rent an 8×H100 node once you want a model that can hold a basic conversation. A few hundred dollars there buys more than a month of local training. Karpathy's nanochat runs the full pipeline on such a node with a single script (see the AI Pioneers page).

nanochat runParametersTime on 8×H100Approx. costResult
d20 speedrun~561M~4 hours~$100Basic chatbot, "like talking to a kindergartener"
GPT-2 referenced24–d26~1.65–3 hours~$50–75Matches or beats 2019 GPT-2 on the CORE benchmark
d321.9B, trained on 38B tokens~33 hours~$800Strongest model the repo targets

Costs assume about $24/hour for the node; spot pricing can be much lower. The same code also runs on one GPU with gradient accumulation, just about 8× slower than a full node. The 5070 Ti has roughly a tenth of an H100's training throughput, so a d20 run at home would take on the order of weeks (approximate).

Learning path and reference code

Write the code yourself once, then switch to a tested codebase for real runs.

  • ☐ Week 1: Karpathy's Neural Networks: Zero to Hero series, through "Let's build GPT" and "Let's build the GPT tokenizer."
  • ☐ Week 2: Write your own ~10M model and train it on TinyStories. Success = coherent stories after about 10 minutes.
  • ☐ Week 3: Follow "Let's reproduce GPT-2 (124M)" from the same series and run the 125M configuration above on FineWeb-Edu overnight.
  • ☐ Week 4: Add chat fine-tuning, export to GGUF, and run the model in Ollama.
  • ☐ Then: Read through nanochat (tokenizer through chat UI in one repo) and run its speedrun on a rented node.

Book-length reference: Sebastian Raschka, Build a Large Language Model (From Scratch) (Manning, 2024), with code on GitHub.
