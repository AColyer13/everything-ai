AI Pioneers

Three researchers whose work shaped modern generative AI: Ian Goodfellow, Andrej Karpathy and Alec Radford. Each section covers what they researched and built, with a timeline. Karpathy also gets a full tour of his GitHub projects.

Not from the class

This page was added on top of the course content. Also, "fathers of AI" is usually a title for the field's earliest founders (Turing, McCarthy, Minsky, Hinton, Bengio, LeCun and others). These three are better described as influential figures of the deep-learning and LLM era, and that is how they are presented here. Timelines come from public sources (Wikipedia, GitHub and the authors' own pages) and may lag behind recent career moves.

Ian Goodfellow

Goodfellow is best known for inventing generative adversarial networks (GANs). The idea: two networks compete. A generator makes fake samples, a discriminator tries to tell fake from real, and each pushes the other to improve until the fakes look real. It is the "GAN" row in the Generative AI table, and it launched a decade of image-synthesis research.

What they researched and created

  • GANs (2014). Introduced in a paper with colleagues at the Université de Montréal, including their PhD advisors Yoshua Bengio and Aaron Courville.
  • Adversarial examples. Co-authored early work showing that tiny, deliberate changes to an input can fool a neural network, and proposed training on such examples as a defence. This founded much of modern AI-security research.
  • Deep Learning (2016). First author of the standard textbook, written with Bengio and Courville and free to read online.

Andrej Karpathy

Karpathy is a researcher, engineer and teacher known for making deep learning understandable. He helped found OpenAI, ran computer vision for Tesla Autopilot, and then built a large following by teaching how language models work from scratch.

What they researched and created

  • Image captioning (PhD, Stanford, advisor Fei-Fei Li). Work combining CNNs and RNNs so a model could describe images and regions in sentences. That is the "hybrid model" idea on the Deep Learning page.
  • The Unreasonable Effectiveness of Recurrent Neural Networks (2015). A blog post and the char-rnn code that showed character-level RNNs writing plausible text, code and Shakespeare.
  • CS231n. Co-created and taught Stanford's convolutional-networks course, which grew from about 150 students in 2015 to about 750 in 2017.
  • Tesla Autopilot Vision. Led the vision team that moved driving perception onto large neural networks trained on fleet data.
  • Zero to Hero (2022 onward). A YouTube series that builds a GPT step by step, from a single neuron up through tokenizers.
  • Eureka Labs (2024). An AI-native education company; its first course is LLM101n.
  • "Vibe coding" (Feb 2025). Coined the term for building software by prompting an AI and accepting its output.

Karpathy's GitHub projects, explained

Profile: github.com/karpathy. This section assumes you have never opened GitHub. If you have, skip to the project map.

Five words you need first

GitHub is a website where programmers publish their code. A repo (repository) is one project's folder on it. A gist is a single shared file or note. Stars are like bookmarks, so a high number means many people found the project useful. An LLM (large language model) is the kind of AI behind ChatGPT: it reads text and predicts what comes next.

Two more that appear a lot: training is teaching a model by showing it lots of examples, and inference is using a finished model to answer something.

The common idea

Most AI code is huge and hard to read. Karpathy's habit is the opposite: shrink a big idea until it fits on one screen, so a person can read every line and understand what the technology really does. Think of it as taking a car engine apart on a table and labelling each part, instead of describing the car from the outside.

Group A: learn how AI works

micrograd

In plain English: a tiny program that shows how a neural network learns. The network makes a guess, measures how wrong it was, and works out which of its internal dials to nudge to be less wrong next time. That "work out which dial to nudge" step is called backpropagation, and micrograd does it in roughly 150 lines on single numbers, so you can follow every step with a pencil.

Why it matters: every modern AI model, including ChatGPT, learns this way. Seeing it at toy size removes the mystery.

Who it is for: anyone who has seen a neural-network diagram and wondered what really happens. Pairs with the Deep Learning page. Open on GitHub

char-rnn

In plain English: one of the first widely shared AI text generators. You give it any text file (Shakespeare, a code base, song lyrics). It learns to guess the next letter, over and over, and then writes new text in the same style, one character at a time. It used an older design called a recurrent neural network, which reads text in order and carries a short-term memory along.

Why it matters: it showed that a simple letter-guessing machine can pick up spelling, grammar and structure by itself, which was a big surprise in 2015 and a stepping stone to today's chatbots.

Who it is for: history and curiosity. It is written in Lua for a framework (Torch) that is no longer used, so read it rather than run it. Open on GitHub

makemore

In plain English: it learns from a list of names and then "makes more" names that sound real. The clever part is that the same task is solved in stages, each smarter than the last, so you can see exactly what each improvement buys you. The last stage uses a Transformer, the design behind ChatGPT.

Why it matters: it is a guided tour from "count which letters follow which" to a modern AI design, using a problem small enough to run on a laptop.

Who it is for: beginners who want to follow along with Karpathy's video lessons. Open on GitHub

minbpe

In plain English: AI models cannot read raw text. First the text is chopped into pieces called tokens (whole words, parts of words, or single characters). minbpe shows the standard way to decide those pieces, called Byte Pair Encoding: start with single characters and keep gluing together the pair that appears most often, until you have a vocabulary of the size you want.

Why it matters: tokens explain odd AI behaviour, such as why a model can struggle to count the letters in a word, and why you are billed "per token". See Token in the glossary.

Who it is for: anyone curious how an AI turns words into numbers. Open on GitHub

microgpt

In plain English: an entire ChatGPT-style system in a single file of about 200 lines of plain Python, with nothing to install. It contains every ingredient: the data, the token handling, the learning engine, the model, the training loop and the text generator. It learns from a list of names and invents new ones. The model is deliberately tiny, so it is a demonstration of the recipe and not a useful chatbot.

Why it matters: it makes the point that the core of a GPT is small. Everything bigger is the same recipe with more data, more computing power and engineering.

Who it is for: anyone with basic Python who wants to see the whole thing at once. This one is a gist (a single shared file), not a full repo. Open the gist

nanoGPT

In plain English: a compact but real GPT. It is small enough to read in an afternoon, and close enough to GPT-2 (an earlier OpenAI model) that it can reproduce a small version of it when given enough data and a powerful graphics card. You can also take an existing model and teach it your own text, which is called fine-tuning.

Why it matters: for years this was the go-to example of how GPT training works. Its popularity (over 60k stars) reflects that. The author has since moved on to nanochat, so treat nanoGPT as the classic version.

Who it is for: people comfortable with Python who want to train a language model for real. Open on GitHub

Group B: build and run a real model

llama2.c

In plain English: Llama 2 is an AI model released by Meta. llama2.c is a program, in one file of the C language, that can run it. You do not need the usual heavy AI toolkits. You can train a small model of the same design, save it, and then run it with this short program.

Why it matters: it showed that running a modern language model does not need a giant software stack. Many people later copied the idea to make AI run on small or unusual devices.

Who it is for: programmers curious how fast, lean AI software is built. Open on GitHub

llm.c

In plain English: normally you train an AI model using a popular toolkit (PyTorch) that hides the details. llm.c trains a GPT-2 model with no toolkit at all, in C and CUDA (the language used to program NVIDIA graphics cards), writing out every calculation by hand. It starts with a simple version and grows into an optimised one.

Why it matters: it reveals what the toolkits do for you, and where the speed comes from. It is the "engine rebuilt from raw metal" version of nanoGPT.

Who it is for: experienced programmers interested in performance. Open on GitHub

nanochat

In plain English: its tagline is "the best ChatGPT that $100 can buy". It covers the whole journey in one small codebase: prepare the text, teach the model language, teach it to hold a conversation, test it, and talk to it in a web page. The $100 refers to renting powerful computers for a short time.

Why it matters: nanoGPT stopped at a model that continues text. nanochat goes on to a model you can chat with, which is the part people actually use.

Who it is for: people who want to see an end-to-end chatbot built without a big company's resources. Open on GitHub

Group C: use AI as a tool

autoresearch

In plain English: an AI assistant runs experiments on its own. It changes the code that trains a small chatbot, trains it for exactly five minutes, checks whether the result got better, keeps the change if so and throws it away if not, then repeats. That is about 12 experiments an hour, or roughly 100 overnight. The human writes the instructions in a plain-text file (program.md) instead of editing the code.

Why it matters: it is a small, concrete example of an "AI agent": software that plans and acts toward a goal with little supervision. The fixed five-minute budget and single score keep the experiments fair.

Who it is for: anyone curious about AI doing research work. Running it needs an NVIDIA graphics card. It is the most-starred repo of the 15. Open on GitHub

llm-council

In plain English: instead of asking one AI a hard question, ask several and let them check each other. Step 1: each model answers separately. Step 2: each model reads the others' answers, with names hidden so none can play favourites, and ranks them. Step 3: one "chairman" model writes the final answer from everything. It runs on your own computer as a web page and reaches many AI providers through a single service called OpenRouter, which needs an account and key.

Why it matters: it applies the "ask a panel, not one expert" idea to AI. It is also a good example of the ensemble idea in Machine Learning.

Who it is for: anyone who wants better answers to hard questions and does not mind some setup. Open on GitHub

llm-wiki.md

In plain English: this one is an idea, not a program. Most AI note tools search your documents from scratch every time you ask a question. This proposes something different: an AI keeps a personal wiki (a set of linked notes) for you. When you add a new article, the AI reads it, writes a summary, and updates the related pages. Over time the wiki gets richer, like a well-kept notebook that someone else tidies for you. Your original sources are never changed, and a rules file tells the AI how to organise things. In technical terms it is an alternative to classic RAG (see Generative AI).

Why it matters: it is a way to build knowledge that accumulates, instead of a chat that forgets. You hand the file to your own AI assistant and it builds the details.

Who it is for: anyone who collects articles and notes. A gist, not a repo. Open the gist

reader3

In plain English: a small demo of reading a book with an AI beside you, so you can ask questions as you go. Karpathy describes it as a quick illustration and says he highly recommends the habit. The README has the exact steps.

Why it matters: it shows an everyday use of AI that needs no technical skill: a patient reading partner.

Who it is for: readers and students. Open on GitHub

rendergit

In plain English: a code project is normally spread across many files and folders. rendergit turns a whole project into one web page that you can scroll through, or paste into an AI so it can read the entire project at once.

Why it matters: it makes it easy to ask an AI "explain this project" or "find the bug", without feeding it files one by one.

Who it is for: anyone who reviews code, human or AI. Open on GitHub

arxiv-sanity-lite

In plain English: arXiv is a free website where researchers post new papers, hundreds a day. This tool lets you tag the ones you like and then suggests similar new ones. It works by measuring how similar the words in two papers' abstracts are, and uses a classic machine-learning method (a support vector machine) to learn your taste. The same idea powers "you might also like" suggestions on shopping and video sites.

Why it matters: a useful product built from older, simple techniques, covered on the Machine Learning page, with no giant model needed.

Who it is for: researchers and students trying to keep up with new papers. Open on GitHub

Where to start

If you are new, read in this order: micrograd, then makemore, then minbpe, then microgpt. That sequence takes you from "how does a network learn?" to "how is a whole GPT put together?". Then try nanochat to see it become a chatbot. Karpathy also has free video lessons (Zero to Hero) that go with the first few.

Alec Radford

Radford is a researcher who works quietly and publishes few papers, but he was first author on several that defined modern generative AI. Much of the field's move from "train a model for one task" to "pretrain a big model, then adapt it" runs through his work.

What they researched and created

  • DCGAN (2015). With Luke Metz and Soumith Chintala, a set of design rules that made convolutional GANs stable to train. It became the template for image GANs, and it also showed that the latent space holds meaningful directions (vector arithmetic on faces).
  • The sentiment neuron (2017). A character-level LSTM trained only to predict the next character on Amazon reviews. One unit ended up tracking sentiment, an early sign that next-token prediction learns useful structure.
  • GPT-1 (2018). Improving Language Understanding by Generative Pre-Training: pretrain a Transformer decoder on unlabelled text, then fine-tune it on a task. This is the origin of the GPT line.
  • GPT-2 (2019). Language Models are Unsupervised Multitask Learners: a much larger model that could perform tasks it was never explicitly trained for. OpenAI at first held back the largest version over misuse concerns.
  • GPT-3 (2020). Co-author of the few-shot learning paper (see few-shot prompting on the Generative AI page).
  • CLIP and DALL-E (2021). CLIP learns images and text in one shared embedding space from captioned pictures and enables zero-shot image classification. DALL-E generated images from text prompts. CLIP is also used inside many diffusion image generators.
  • Whisper (2022). A robust speech-recognition and translation model trained on a large amount of weakly supervised audio.

The common thread

All three worked on the same arc. Goodfellow's GANs showed that networks could generate convincing data. Radford's DCGAN, GPT, CLIP and Whisper work showed that large generatively pretrained models transfer to many tasks. Karpathy then taught the field how those systems are built, with code short enough to read. If you want to follow the arc yourself, read Deep Learning, then Generative AI, then work through micrograd, makemore and nanoGPT in that order.
