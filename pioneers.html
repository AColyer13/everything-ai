AI Pioneers

Three researchers whose work shaped modern generative AI: Ian Goodfellow, Andrej Karpathy and Alec Radford. Each section covers what they researched and built, with a timeline. Karpathy also gets a full tour of his GitHub projects.

Not from the class

This page was added on top of the Simplilearn course content. Also, "fathers of AI" is usually a title for the field's earliest founders (Turing, McCarthy, Minsky, Hinton, Bengio, LeCun and others). These three are better described as influential figures of the deep-learning and LLM era, and that is how they are presented here. Timelines come from public sources (Wikipedia, GitHub and the authors' own pages) and may lag behind recent career moves.

Ian Goodfellow

Goodfellow is best known for inventing generative adversarial networks (GANs). The idea: two networks compete. A generator makes fake samples, a discriminator tries to tell fake from real, and each pushes the other to improve until the fakes look real. It is the "GAN" row in the Generative AI table, and it launched a decade of image-synthesis research.

What they researched and created

  • GANs (2014). Introduced in a paper with colleagues at the Université de Montréal, including their PhD advisors Yoshua Bengio and Aaron Courville.
  • Adversarial examples. Co-authored early work showing that tiny, deliberate changes to an input can fool a neural network, and proposed training on such examples as a defence. This founded much of modern AI-security research.
  • Deep Learning (2016). First author of the standard textbook, written with Bengio and Courville and free to read online.

Andrej Karpathy

Karpathy is a researcher, engineer and teacher known for making deep learning understandable. He helped found OpenAI, ran computer vision for Tesla Autopilot, and then built a large following by teaching how language models work from scratch.

What they researched and created

  • Image captioning (PhD, Stanford, advisor Fei-Fei Li). Work combining CNNs and RNNs so a model could describe images and regions in sentences. That is the "hybrid model" idea on the Deep Learning page.
  • The Unreasonable Effectiveness of Recurrent Neural Networks (2015). A blog post and the char-rnn code that showed character-level RNNs writing plausible text, code and Shakespeare.
  • CS231n. Co-created and taught Stanford's convolutional-networks course, which grew from about 150 students in 2015 to about 750 in 2017.
  • Tesla Autopilot Vision. Led the vision team that moved driving perception onto large neural networks trained on fleet data.
  • Zero to Hero (2022 onward). A YouTube series that builds a GPT step by step, from a single neuron up through tokenizers.
  • Eureka Labs (2024). An AI-native education company; its first course is LLM101n.
  • "Vibe coding" (Feb 2025). Coined the term for building software by prompting an AI and accepting its output.

micrograd

A tiny automatic-differentiation engine that works on single numbers, plus a small neural-network library on top with a PyTorch-like feel. Every operation records how to compute its own gradient, and calling backward() walks the graph applying the chain rule. It is the clearest demonstration of the backpropagation step described on the Deep Learning page, and it pairs with Karpathy's first Zero to Hero lecture. Repo

char-rnn

Multi-layer recurrent networks (plain RNN, LSTM and GRU) for character-level language models, written in Lua for the Torch framework. You feed it any text file, it learns to predict the next character, and then it generates new text in the same style. Together with the 2015 blog post it popularised the idea that sequence models learn spelling, syntax and structure from raw characters alone. It is historical now (Torch is retired) but it set up everything that followed. Repo

makemore

A character-level autoregressive model that "makes more" of whatever you give it; the running example is a file of names that it learns to invent. The same task is solved with progressively better models: bigram counts, an MLP, an RNN and finally a Transformer, which makes it a good way to see why each step helped. It is the code behind the Zero to Hero lectures. Repo

nanoGPT

Described as the simplest, fastest repository for training and fine-tuning medium-sized GPTs. The model and the training loop are each a few hundred lines in PyTorch, close enough to GPT-2 that it can reproduce the small GPT-2 model on OpenWebText, yet short enough to read in one sitting. For years it was the default teaching codebase for how GPT training works. The repo has been largely superseded by nanochat. Repo

minbpe

Minimal, clean code for Byte Pair Encoding, the tokenizing method behind GPT-style models. BPE starts from raw bytes and repeatedly merges the most frequent adjacent pair into a new token until the vocabulary reaches a target size. The repo includes a basic tokenizer, a regex-split version in the GPT-4 style, and training and encode/decode paths. It makes the token entry in the glossary concrete. Repo

llama2.c

Llama 2 inference in a single file of pure C. You can train small Llama-2-architecture models in PyTorch, export the weights, and then run them with a program of a few hundred lines and no dependencies. It showed that running a modern LLM does not require a heavy framework, and it inspired a wave of tiny "run it anywhere" ports. Repo

llm.c

LLM training in simple, raw C and CUDA. It reimplements GPT-2 training without PyTorch or Python: every forward and backward pass is hand-written. It starts with a plain C reference and grows into optimised CUDA kernels, so you can read exactly what a framework does for you and see where the speed comes from. Repo

nanochat

Tagline: "the best ChatGPT that $100 can buy." It is a complete, minimal pipeline from raw text to a chat model: tokenizer training, pretraining, fine-tuning, evaluation, inference and a web chat interface, in one small codebase run from a handful of scripts. Where nanoGPT covered only pretraining, nanochat covers the whole path to a conversational assistant, and it is meant to be read and modified. Repo

microgpt

Published as a gist rather than a repo. A single dependency-free Python file of about 200 lines (standard library only) that contains the dataset handling, a tokenizer, an autograd engine, a GPT-2-style Transformer, the Adam optimizer, a training loop and sampling. It trains on a list of names and then invents new ones. The model is deliberately tiny (one layer, 16-dimensional embeddings, four attention heads). It is the "everything at once" counterpart to micrograd. Gist

autoresearch

AI agents running research on small single-GPU nanochat training. An agent edits one file (train.py: model, optimizer, training loop), trains for a fixed five minutes, checks whether validation bits-per-byte improved, keeps or discards the change and repeats. That is about a dozen experiments an hour, or roughly a hundred overnight. The human edits the instruction file program.md instead of the Python. It is a small-scale look at automated AI research and at what "agentic AI" (see Generative AI) can do with a clear metric. Repo

llm-council

A local web app that asks several LLMs the same question. In stage one each model answers on its own. In stage two each model reads the others' answers (with the authors hidden) and ranks them. In stage three a designated "chairman" model writes the final answer. It uses a FastAPI backend, a React front end and OpenRouter to reach many providers through one API key. It is a hands-on example of the ensemble idea from Machine Learning, applied to language models. Repo

llm-wiki.md

An "idea file" published as a gist: a pattern, not an app. Instead of retrieving raw documents on every question (RAG), an LLM builds and maintains a persistent set of interlinked markdown pages. There are three layers: raw sources the LLM never edits, the wiki it writes, and a schema file (such as CLAUDE.md) that sets the rules. The main operations are ingest, query and lint, with an index.md and a log.md for navigation. You give the file to your own agent and let it implement the details. Gist

reader3

Described by its author as a quick illustration of how easily you can read books together with an LLM, and one he highly recommends. It is a small demo of an everyday workflow (reading with a model beside you) rather than a framework. Check the README for the exact mechanics. Repo

rendergit

Renders any git repository into a single static HTML page, meant to be read by humans or handed to an LLM. Useful when you want a model (or a person) to skim a whole codebase in one place. Repo

arxiv-sanity-lite

A lighter rewrite of the earlier arxiv-sanity tool. You tag papers you care about, and it recommends similar new arXiv papers in a simple UI. The recommender is classical ML from this course: TF-IDF features of the abstracts fed to a support vector machine. A good example of a useful product built from "old" techniques rather than a giant model. Repo

Alec Radford

Radford is a researcher who works quietly and publishes few papers, but he was first author on several that defined modern generative AI. Much of the field's move from "train a model for one task" to "pretrain a big model, then adapt it" runs through his work.

What they researched and created

  • DCGAN (2015). With Luke Metz and Soumith Chintala, a set of design rules that made convolutional GANs stable to train. It became the template for image GANs, and it also showed that the latent space holds meaningful directions (vector arithmetic on faces).
  • The sentiment neuron (2017). A character-level LSTM trained only to predict the next character on Amazon reviews. One unit ended up tracking sentiment, an early sign that next-token prediction learns useful structure.
  • GPT-1 (2018). Improving Language Understanding by Generative Pre-Training: pretrain a Transformer decoder on unlabelled text, then fine-tune it on a task. This is the origin of the GPT line.
  • GPT-2 (2019). Language Models are Unsupervised Multitask Learners: a much larger model that could perform tasks it was never explicitly trained for. OpenAI at first held back the largest version over misuse concerns.
  • GPT-3 (2020). Co-author of the few-shot learning paper (see few-shot prompting on the Generative AI page).
  • CLIP and DALL-E (2021). CLIP learns images and text in one shared embedding space from captioned pictures and enables zero-shot image classification. DALL-E generated images from text prompts. CLIP is also used inside many diffusion image generators.
  • Whisper (2022). A robust speech-recognition and translation model trained on a large amount of weakly supervised audio.

The common thread

All three worked on the same arc. Goodfellow's GANs showed that networks could generate convincing data. Radford's DCGAN, GPT, CLIP and Whisper work showed that large generatively pretrained models transfer to many tasks. Karpathy then taught the field how those systems are built, with code short enough to read. If you want to follow the arc yourself, read Deep Learning, then Generative AI, then work through micrograd, makemore and nanoGPT in that order.
